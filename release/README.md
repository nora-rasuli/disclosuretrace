# DisclosureTrace release workspace

> Private, blocked release material. The independent audit records `Not ready`
> and the originality gate records `Pivot`. Nothing in this directory is
> approved for publication unless the product materially pivots, passes a new
> originality gate, and then clears every technical re-audit requirement.

This directory keeps publication preparation separate from the application and
its implementation evidence. It does not change repository visibility,
deployment protection, GitHub metadata, the live portfolio, or the project's
Factory status.

## Contents

- `publication-blockers.md` — current gate state and the exact actions withheld.
- `deployment-verification-plan.md` — release and rollback verification sequence.
- `post-launch-check.md` — blank dated record for the first public verification.
- `drafts/github-readme.md` — proposed public README copy, explicitly unapproved.
- `drafts/portfolio-case-study.md` — proposed portfolio narrative, explicitly unapproved.
- `drafts/repository-metadata.md` — proposed description, topics, social-preview copy, and alt text.
- `drafts/claims-ledger.md` — draft public claims mapped to existing evidence and audit disposition.
- `drafts/hiring-manager-review.md` — presentation-gate worksheet to run after the audit.
- `drafts/screenshot-manifest.md` — screenshot selection and recapture requirements.
- `drafts/assets/social-preview.svg` — private 1280×640 social-preview source.

## Promotion rule

The publishing chat may promote these drafts into public locations only after:

1. a material workflow pivot passes a new originality gate;
2. a re-audit records a publication-permitting decision;
3. every P0/P1 finding is resolved and re-audited;
4. the approved claims ledger is reconciled with the final commit and deployment;
5. screenshots are recaptured from that final build under the approved product name;
6. Nora separately authorizes each external state change.
